# 派工模板 — 研究 / 查證

> 用途：查官方文件、比較方案、確認 API 用法、蒐集外部資訊。
> 派給：Claude Code / Anthropic API 問題 → `claude-code-guide`；其他 → `general-purpose`（sonnet）。
> 研究產物一律落檔——主對話只收結論，全文進筆記檔。

## Prompt 模板（複製後填空）

```text
問題：{{要回答的問題，寫成可以被「是/否/清單/數字」回答的形式}}。
動機：{{拿答案去做什麼決定}}——回答的深度以「足夠做這個決定」為準，不用寫論文。

查證要求：
1. 優先序：官方文件 > 官方 repo/changelog > 高信譽技術文章 > 論壇。每個結論標出處 URL
2. 區分三種陳述並標記：【事實】（有出處）／【推論】（你從事實推的）／【未查到】
3. 版本敏感的資訊（API、參數、pricing）MUST 標注文件日期或版本號
4. 查不到就寫「未查到」——NEVER 用訓練記憶補洞充當查證結果

驗收條件：
1. 問題有直接答案（或明確回答「查不到，最接近的是 ___」）
2. 每個【事實】都有 URL；沒有任何無出處的斷言
3. {{題目特定條件，例：至少比較 3 個方案的 X/Y/Z 三個維度}}

回報格式：
- 全文筆記落檔到 {{路徑，例：專案 scratchpad / Notes 目錄}}
- 回主對話只給：答案（≤5 行）+ 關鍵出處（≤3 個 URL）+ 筆記檔路徑
- 總長 ≤15 行
```

## 填空要點

- 問題形式決定答案品質：「X 怎麼樣？」→ 散文；「X 支援 Y 嗎？限制是什麼？」→ 可驗收
- 【事實】/【推論】/【未查到】三分法是本模板的核心——弱模型最常見的失敗是把記憶當查證
- 要做「主題式深入研究 + 整理成 wiki」→ 改用 `/research-note` skill，不用本模板
- ❌ 常見錯誤：不給動機——subagent 不知道要多深，回來一篇 200 行還沒回答你真正要決定的事
