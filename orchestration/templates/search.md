# 派工模板 — 搜尋 / 盤點

> 用途：找「哪裡有 X」「影響面多大」「這功能在哪實作」。
> 派給：`Explore`（subagent_type）；model 呼叫參數給 `sonnet`，單一目錄小範圍可給 `haiku`。
> 原則：主對話 NEVER 自己掃 repo（`dispatch.md §critical_notes`）。

## Prompt 模板（複製後填空）

```text
目標：找出 {{找什麼：symbol / pattern / 設定 / 功能位置}}。
動機：{{為什麼要找：接下來要改它 / 評估影響面 / 確認是否已存在}}——這影響你該回報到多細。

範圍：{{目錄或 repo 根路徑}}；排除 {{node_modules / bin / .git / 測試檔…}}。
搜尋深度：{{medium｜very thorough——跨多目錄、多命名慣例時用 very thorough}}

驗收條件：
1. 每個命中列出 檔案:行號 + 一行說明（它在這裡扮演什麼角色）
2. 附上你用過的搜尋 pattern 清單（供查核有沒有漏——例如同義詞、別名、縮寫）
3. 明確回答「除了列出的，還有沒有可能漏網」：說明你排除了哪些目錄與理由

回報格式：
- 表格：檔案:行號｜角色｜備註，總長 ≤25 行
- NEVER 貼程式碼原文（每處最多 1 行引用）
- 命中超過 20 處 → 落檔到 {{路徑，例：專案 scratchpad}}，回報只給分類統計 + 檔案路徑
```

## 填空要點

- 「動機」決定回報粒度：要改它 → 需要行號級；只是確認存在 → 檔案級即可，寫清楚省 token
- 搜尋 pattern 清單是驗收重點：沒有它就無法判斷「找到 3 處」是全貌還是漏找
- ❌ 常見錯誤：`幫我找找 HttpClient 相關的東西`——「相關的東西」無法驗收，回來一定是散文
